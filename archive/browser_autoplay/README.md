# LinkedIn 謎題 - 網頁自動填答

在電腦 Chrome 上打開謎題後，這個工具會**擷取畫面 → 辨識題目 → 求解 → 自動移動滑鼠填答**。

支援 Tango / Queens / Mini Sudoku / Zip / Patches 五種謎題。

> 這是獨立的新專案，**完全沒有修改** `../tango_solver`。
> 辨識與求解邏輯是用 `import` 的方式重用既有專案（見 `solver_bridge.py`）。

## 使用方式（GUI）

先在 Chrome 開好謎題頁面（例如 `linkedin.com/games/patches/`），讓棋盤完整顯示。
然後雙擊 `dist/PuzzleAutoPlay.exe`（或開發模式 `python gui.py`）：

1. **棋盤位置** — 用固定座標，預設值是「螢幕水平置中、往下 200px、640x700」，
   對 1920x1080 且瀏覽器最大化的情況剛好涵蓋棋盤。
   第一次先按「**測試擷取範圍**」，確認預覽圖裡有完整棋盤；不對就改 X/Y/寬/高 再測。
   設定會自動記住（存在 `~/.linkedin_puzzle_autoplay.json`）。
2. **選項** — 謎題類型預設自動判斷；`預演模式` 預設**開啟**。
3. **執行** — 按「**開始自動解答**」。預演模式下只會列出打算怎麼點；
   確認無誤後取消勾選 `預演模式`，再按一次就會真的填答。

> **不提供拖曳框選功能**：在同一個程式裡再開第二個 `tk.Tk()` 根視窗會讓整個視窗崩潰
> （原本的框選功能就是這樣壞掉的）。改用可直接輸入的固定座標 + 預覽按鈕。

### 安全機制

- **預設不會真的點擊**。要實際操作滑鼠，必須自己取消勾選「預演模式」，
  而且會再跳一次確認視窗。
- 執行前有倒數（預設 4 秒），可以趁機把 Chrome 切到最前面。
- 執行中可以按「停止」，或**把滑鼠快速移到螢幕左上角 (0,0)** 觸發緊急中止。
- 填完後會重新擷取畫面檢查有沒有漏填，並自動補點（見下方「驗證與補點」）。

## 使用方式（命令列）

```bash
python autoplay.py                          # 用預設固定位置，預演（不會點擊）
python autoplay.py --go                     # 用預設固定位置，實際自動填答
python autoplay.py --region 640,200,640,700 # 自己指定螢幕區域
python autoplay.py --window chrome --go     # 擷取 Chrome 視窗並填答
python autoplay.py --image shot.png         # 用圖片檔測試辨識（不會點擊）
```

常用參數：

- `--go`：真的操作滑鼠（不加就只是預演）
- `--type {tango,queens,sudoku,zip,patches}`：指定謎題類型
- `--countdown N`：開始前倒數秒數
- `--retry N`：填完後檢查並補點的輪數（預設 1，設 0 關閉）
- `--save shot.png` / `--save-overlay debug.png`：存下擷取畫面 / 辨識疊圖，用來排查辨識問題

## 驗證與補點

自動點擊不保證每一下都被網頁收到（頁面還在載入、動畫進行中都可能吃掉點擊）。
所以填完之後會**重新擷取畫面、重新辨識**，比對目前畫面與正確答案，把沒填到的格子補點。

- **Tango / Mini Sudoku**：支援驗證與補點（畫面上的太陽月亮、數字都讀得出來）
- **Queens / Zip / Patches**：作答結果是皇冠 / 路徑線 / 切割線，既有專案沒有對應的辨識器，
  所以只會回報「無法自動驗證」，需要自己看畫面確認

## 檔案結構

- `solver_bridge.py`：橋接 `../tango_solver`（只匯入、不修改）
- `capture.py`：螢幕擷取（整個螢幕 / 指定視窗 / 拖曳框選區域）
- `board_mapper.py`：把「第 r 列第 c 欄」換算成螢幕絕對座標
- `solve_puzzle.py`：辨識 + 求解，回傳填答需要的結構化資料（含尺度正規化，見下方）
- `players.py`：把解答轉成滑鼠操作序列（各遊戲操作方式不同）
- `input_driver.py`：滑鼠鍵盤驅動，含預演模式、緊急中止、點擊間隔控制
- `verify.py`：填答後重新辨識、比對、產生補點計畫
- `gui.py` / `autoplay.py`：GUI 與 CLI 入口
- `tests/test_end_to_end_screen.py`：把題目畫到真實螢幕 → 擷取 → 辨識 → 求解 → 驗證座標落點
- `tests/test_real_clicks.py`：**實際移動滑鼠點擊**，驗證點擊真的落在正確格子上

## 已知重要細節（踩過的坑）

- **同一格連點太快會被當成「雙擊手勢」**：實測在同一點快速連點，作業系統會把它們
  歸類成雙擊 / 三擊（Tk 收到的是 `<Double-Button-1>` 而不是兩個 `<Button-1>`）。
  遊戲若是靠「點兩下 = 兩次獨立點擊」來循環狀態（Tango 的 空白→太陽→月亮），
  連點太快就可能只算一次。所以同一格連點之間固定間隔 `SAME_SPOT_CLICK_GAP = 0.55s`
  （Windows 預設雙擊判定是 500ms）。

- **移動滑鼠後要等一下再按**：移到目標後立刻點擊，實測會有相當比例的點擊沒被收到
  （9/18 → 加了 0.15s 緩衝後 18/18）。網頁通常要先收到 mousemove/hover 才會把該格
  視為作用中。這個緩衝時間是 `InputDriver.settle_after_move`。

- **辨識前要把棋盤正規化到約 800px**：既有專案的辨識門檻與數字範本都是在手機截圖
  （棋盤約 800px）上校準的。網頁上的棋盤大小不一定，直接辨識會不穩
  （實測 Patches 在棋盤 506px/635px 可行，但 529~719px 之間會把標籤數字讀錯）。
  所以會先找到棋盤、把整張畫面縮放成「棋盤約 794px」再辨識，
  最後再把座標換算回原始畫面。正規化之後從 428px 到原尺寸都能穩定辨識。

- **棋盤太小辨識會失準**：建議棋盤至少 500px（`MIN_BOARD_PIXELS`）。
  太小的話在 Chrome 按 `Ctrl` + `+` 放大頁面即可。

- **全螢幕程式會吃掉點擊**：如果有全螢幕程式（例如遊戲）蓋在最上層，
  滑鼠點擊會送到它而不是瀏覽器。填答前請確認 Chrome 在最前面。

- **「辨識成功」不等於「辨識正確」**：這是最危險的失敗模式。實測 Tango 的棋盤縮到
  約 390px 時，4 個 `=`/`×` 符號只會抓到 1 個 —— 求解器仍然會吐出一組「符合它看到的
  那些條件」的答案，但那是**錯的答案**，而且不會報錯。
  解法是用**解的唯一性**當作辨識完整度的檢查：真正的 Tango / 數獨題目一定只有一組解，
  如果偵測到的條件允許多組解，就代表漏讀了東西，直接判定失敗並換個裁切/縮放重試。
  加上這個檢查後，各種擷取範圍大小都能得到正確答案。

- **Patches 有「沒有數字」的標籤**：規則是「如果形狀內標有數字，則其大小必須與該數字
  相符」，所以沒標數字 = 大小不限，只受形狀型別限制。既有專案要求每個標籤都要有數字，
  遇到空白標籤會直接報錯。`patches_ext.py` 在不修改既有專案的前提下擴充支援。
  分辨方式：切不出任何字形 → 空白標籤；切得出字形但認不出來 → 才是辨識失敗。

- **不要用拖曳框選**：在同一個程式裡再開第二個 `tk.Tk()` 根視窗會讓整個視窗崩潰。
  已改為固定座標 + 預覽。

## 待驗證（需要實際網址）

以下都還沒在真實網頁上測過，因為目前還沒有網址：

1. **各遊戲的點擊語意**。目前依畫面說明實作：
   - Tango：點 1 下 = 太陽、點 2 下 = 月亮（假設空白→太陽→月亮循環）
   - Queens：點 2 下 = 皇后（畫面說明「輕點一次放置 X，輕點兩次放置皇后」）
   - Sudoku：點格子 → 按數字鍵
   - Zip：從編號 1 按住拖曳走完整條路徑
   - Patches：每塊矩形從左上角拖到右下角

   這些設定都集中在 `players.py` 各 Player 的 class 屬性，實測後可直接調整。
   **請務必先用預演模式看動作是否合理，再實際執行。**

2. **網頁版的畫面配色 / 尺寸** 是否與手機版一致。若辨識不準，
   用 `--save shot.png` 存下畫面，就能據此調整。
